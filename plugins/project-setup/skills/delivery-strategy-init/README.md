# delivery-strategy-init

Creates or adopts one project-specific Delivery strategy, normally at `docs/delivery-strategy.md`. An agent invokes the skill on the user's behalf.

## What it produces

The initialized document contains:

- an evidence-scoped current delivery mode and ordinary-change expectation;
- a complete progressive activation index;
- real Delivery Units and per-unit reachability;
- artifact identity, provenance, transformation, and lineage when applicable;
- non-linear Delivery Step graphs with explicit outcomes and recovery edges;
- the one-way seam from delivery controls to Testing gates/scopes;
- actor-neutral review, disposition, approval, exception, and recovery records.

An unfamiliar prototype gets a compact statement that no delivery path is established. The skill does not invent CI, packages, stages, deployments, store mechanics, approvals, rollback, or operational history.

## Safety and composition

The initializer searches for existing or equivalent policies before creating a canonical owner, preserves user prose outside managed regions, and applies one confirmed exact-byte proposal through the shared recoverable project-setup protocol. It changes root strategy routes only when it can reconcile `CLAUDE.md` and `AGENTS.md` symmetrically.

The skill changes documentation only. It does not build, publish, deploy, expose, install dependencies, create credentials, or mutate remote services.

## Relationship to other skills

- `testing-strategy-init` owns Verification Scopes and Gate interpretation; Delivery strategy owns evidence consumers and consequences.
- `git-strategy-init` owns source integration, worktrees, commits, pull requests, and merge mechanics.
- `pitfalls-docs-init` records learned traps rather than normative delivery policy.
- `project-init` invokes this initializer after Testing strategy setup.
