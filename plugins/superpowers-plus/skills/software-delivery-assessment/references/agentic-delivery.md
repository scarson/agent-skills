# Agentic delivery overlay

Apply this overlay per delivery unit and change class when agents materially author, approve, operate, or release changes. Record `not_applicable` where agents have no material role. Weak continuous-delivery foundations do not suppress the overlay. Assess those foundations through the core capability model, then use this overlay to identify risks that agent speed, autonomy, or fan-out can compound.

Keep evidence ceilings intact. Repository policies, specifications, workflows, and evaluation definitions support declared or configured claims. Attributed testimony remains claimed. Provider events, review records, gate results, agent activity, promotions, and evaluation results support demonstrated claims only for the observed actor, predicate, path, revision, conditions, and window. A document that calls itself authoritative proves only that the document makes that claim.

## Foundational readiness under agent speed

- Which integration, verification, artifact, release, and recovery controls govern this agentic change class?
- Does trustworthy feedback arrive before the agent can compound an error through another change, queue entry, or release action?
- Where do weak or missing delivery foundations let agent throughput increase batch size, review pressure, coupling, or consequence?

Report each foundation gap through the ordinary capability model. Use this domain to explain the added exposure created by the agent's pace and reach.

## Specification and authority

- Which durable artifacts state intent, affected behavior, constraints, allowed scope, and acceptance evidence before implementation?
- Which independently attributable governing decision or independently operated control adopts each artifact for this delivery unit and change class?
- Can the authoring agent create or change the specification, tests, policy, or acceptance evidence that judges its own output, and which control resolves a conflict?
- Do permissions and supplied context bind the agent to the intended unit, paths, task, controls, secrets, and environments?

An agent-authored artifact can govern when an independently attributable governing decision or independently operated control adopts it for the artifact and scope. The artifact's own authority statement remains a claim.

## Bounded work and review WIP

- Can one agent-authored change remain small enough for independent review, diagnosis, recovery, and release?
- How many agent-authored changes may enter implementation or review at once, and what happens when the review queue grows?
- Does a red material gate pause new feature work and restrict activity to restoring the gate before the agent expands the batch?
- Which records show actual change size, concurrency, queue delay, review outcomes, and pauses rather than policy or configuration alone?

Separate the configured work limit from observed behavior. A small-session rule has no demonstrated effect until change, queue, or review records show its use.

## Enforcement and consequence separation

- Which provider or control evidence shows that required gates constrain agent-authored changes and resist bypass or weakening by the authoring agent?
- Can the agent approve, promote, deploy, publish, change policy, or alter an environment through the same authority it uses to author the change?
- Do review approval, promotion, and release remain separate decisions where their consequences differ?
- Does an independent control match the consequence of each action without imposing a universal human-review rule?

Judge independence by control authority and operation. A human actor may supply that control, but this overlay does not require one for each change.

## Provenance, recovery, and evaluation

- Can an assessor connect governing intent, task and agent identity, source revision, proof, artifact, approval, promotion, and destination for a consequential action?
- Can the system stop, contain, reverse, restore, or move forward from agent-caused failure, and which recovery behavior has been exercised?
- Do evaluation definitions cover representative success and failure behavior, and do result records bind each conclusion to a named task, revision, conditions, and window?
- Do anomaly and outcome records support conclusions with real events and denominators rather than configured checks, retained transcripts, or guessed metrics?

Keep evaluation definitions at the configured ceiling. Results demonstrate only the named cases and result window; they do not establish general agent reliability.

**Exclusions:** Do not add an agentic maturity score, universal numeric threshold, mandatory human review, provider or evaluation framework, artifact taxonomy, transcript-retention requirement, model or prompting guidance, token metric, or multi-agent architecture. Recommend a change only when evidence shows that it would alter a delivery decision, constraint, or material uncertainty.
