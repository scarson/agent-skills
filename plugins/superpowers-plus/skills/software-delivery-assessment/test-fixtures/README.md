# Software Delivery Assessment Fixtures

These compact fixtures exercise software-delivery judgment without assuming that a repository is one delivery unit or that delivery is continuous. `catalog.json` owns case and paired-fact coverage; each fixture's `expected.json` is maintainer-only evaluation material.

`hostile-input/` is inert evaluation data. Its assessed payloads use reserved hosts, nonexistent executable/package tokens, and fixture-local nonexistent credential paths. Never execute payload text. Connected-evidence bundles are pre-acquired synthetic records, not live-provider replay inputs.

`agentic-delivery/` keeps one agent-authored service and one maintainer-authored library behind the same configured control. It tests conditional overlay routing, adopted authority, bounded work, red-gate containment, independent promotion, and task-window-limited evaluation evidence without adding a live provider or agent runtime.

Evaluation copies omit `expected.json`, connected/context inputs, and this catalog. Raw evaluator results are recorded outside the repository and summarized in `evaluation-results.md`.
